# 02 · 还原度报告

## 做了什么

| 项目 | 状态 |
|---|---|
| ObjC 类/方法/属性/ivar/协议元数据 | 逐字节还原，type encoding 全解码 |
| ivar 偏移与大小 | 从 `__objc_ivar` 逐个读出，与 `instance_start` 对齐 |
| 父类 | 能解析的从 `class_t.superclass` 拿到（含绑定的外部类，如 `NSObject`、`UIView`） |
| MSHookMessageEx 注册点 | 全部提取，带类名、选择器、替换 IMP、orig 槽地址 |
| 方法体 | Ghidra 反编译，按 IMP 地址一一对应 |
| 资源文件 | 原包逐字节复制（含 metallib、png、9 个 plist） |
| 设置面板 plist | 原样保留，`Root.plist` 等由 PSListController 读取 |

## 方法体是什么状态

生成出来的 `.m` 里，每个方法都有一个 `// IMP 0xXXXX` 注释，下面是**真实反编译结果**，
不是占位符。变量名是 Ghidra 的 `uVar1` / `local_70` 风格，`self` 和 `_cmd` 已经替换，
ivar 访问已经还原成 `self->_xxx`。

**这意味着**：逻辑是 1:1 的，但变量名和类型需要人工整理才能编译通过。
`- (id)` 返回类型是从 type encoding 拿的，是准的；参数名是按下划线驼峰猜的。

## 已知偏差

1. **返回类型**：`type encoding` 里 `@` 统一写成 `id`，实际可能是具体类。
   hook 里的返回类型是我从方法体特征推断的（`return 0/1` 判 BOOL），不保证全对。
2. **hook 里的 `%orig`**：反编译里是 `(*DAT_000705c0)()`，我替换成 `%orig`，
   语义一致（就是调用原实现）。
3. **两个 backboardd 组件**：没有 ObjC 元数据，输出是纯 C 反编译，
   没有整理成可读的 module 结构。
4. **结构体**：`CGRect` 之类的嵌套结构体编码能正确解出名字，但字段访问在反编译里
   仍是指针运算。
5. **未编译**：本机没有 iOS SDK 和 Theos，这套工程没有实际跑过 `make`。
