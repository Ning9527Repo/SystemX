## 每个二进制都做了什么

- 全部 10 个切片（含 arm64e）都跑了完整反编译，不是只做 arm64。
- 每个切片都从 load command 解析 chained fixups，指针逐个还原（`PTR_64_OFFSET`
  的 bind 位在 bit 63，rebase 目标 36 位，需要区分对待）。
- 相对方法表（`__objc_methlist`）的 name 字段指向 selref 槽位而不是字符串，
  代码里做了一次间接解引用，否则方法名会全是乱码。
- 方法 IMP 与反编译函数按地址一对一配对，不存在错位。

## 那个 29,036 字节的构造器

`SystemBox` 里 0xaf88 起的函数是 Logos 生成的注册器，521 条 `MSHookMessageEx`
全在里面。它太大，Ghidra 反编译直接失败（`decompile failed`）。

处理方式：不做假的 C，改用**带注解的完整汇编**——`Analysis/disasm/SystemBox_LogosConstructor.asm`，
7,756 行，每条 `MSHookMessageEx` 调用点都标了从寄存器状态还原出来的类名和选择器。
同时这 521 条注册也单独整理成了 `src/SystemBox/Hooks.xmi` 的 Logos 源码，
所以逻辑没有丢。
